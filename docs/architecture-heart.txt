===============================================================================
               PARTNERVERSE - EL CORAZÓN DE LA ARQUITECTURA SAAS
===============================================================================

Este documento detalla el núcleo operativo, técnico y de seguridad de la 
plataforma PartnerVerse, sirviendo como guía de ingeniería para producción.

1. EL NÚCLEO DE LA APLICACIÓN (EL MOTOR DE ATRIBUCIÓN)
-------------------------------------------------------------------------------
El "corazón" de PartnerVerse es el SISTEMA DE RASTREO Y LIQUIDACIÓN AUTOMATIZADA.
Su función principal es vincular la identidad de un Partner con la actividad 
de un cliente final en plataformas externas mediante tres pilares:

A. El Enlace de Seguimiento (/aff/[code]):
   Captura el tráfico, registra el 'click' en el perfil del Partner y deposita 
   una cookie/localStorage de persistencia (30 días) en el navegador del cliente.

B. Los Endpoints de Conversión (API Affiliate):
   Permiten que cualquier SaaS externo (ej. Menfy) reporte una venta enviando 
   el 'code' del socio. El sistema valida al socio, calcula la comisión según 
   el plan oficial en 'saasPlatforms' y genera una transacción aprobada.

C. Jerarquía Multinivel:
   Cada socio puede tener un 'parentId'. El sistema está diseñado para que en 
   futuras versiones, una venta genere comisiones en cascada para la línea 
   ascendente de liderazgo.

2. ARQUITECTURA DE DATOS (FIRESTORE DE ALTA DISPONIBILIDAD)
-------------------------------------------------------------------------------
La base de datos está diseñada bajo el principio de "Aislamiento por Rol":

* /users/{userId}: Identidad y permisos (superadmin vs admin).
* /partners/{partnerId}: Perfil comercial, métricas de clics/registros y 
  configuración de Tiers (Silver, Gold, Platinum).
* /saasPlatforms/{platformId}: El cerebro del negocio. Define los dominios, 
  precios oficiales de planes y porcentajes de comisión.
* /transactions/{txId}: El libro contable. Registros inmutables de cada dólar 
  generado, vinculando al socio con el referido.
* /referrals/{refId}: Registro de clientes (ej. restaurantes) y sus estados 
  (registrado, pendiente, activo).

3. EL MOTOR DE SEGURIDAD (FIRESTORE RULES)
-------------------------------------------------------------------------------
El perímetro de seguridad no confía en el cliente:
* Validación de Propiedad: Un Partner solo puede ver documentos donde 
  'partnerId == auth.uid'.
* Cortocircuito CEL: Las reglas validan primero la autoría del recurso antes 
  de consultar roles, optimizando costos de lectura (get).
* Restricción de Escritura: Los Partners tienen prohibido alterar montos de 
  comisiones o estados de pago; estas son operaciones exclusivas del SuperAdmin 
  o del sistema vía API protegida.

4. FLUJO OPERATIVO MULTINIVEL
-------------------------------------------------------------------------------
1. Registro: El socio obtiene su 'referralCode' único (UID-8).
2. Prospección: El socio comparte su URL única generada dinámicamente.
3. Conversión: El cliente se registra. El sistema crea un 'referral' y una 
   'transaction' vinculada.
4. Auditoría: El SuperAdmin verifica activaciones manuales en el panel de 
   'Activaciones' para aprobar comisiones de alta cuantía.
5. Liquidación: El sistema consolida las transacciones en 'payments' para el 
   desembolso final.
